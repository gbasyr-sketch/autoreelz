# Автомобили и модификации в совместимости

12.10.2026 владелец поручил редактировать автомобили прямо в блоке совместимости manager. Текущий выпуск — [status.md](status.md).

## Как пользоваться

В форме товара откройте «Характеристики и совместимость» и добавьте правило, если его ещё нет. Рядом со списком «Автомобиль» доступны **«+ Автомобиль»** и **«Изменить автомобиль»**; рядом с модификацией — аналогичные кнопки. Редактирование доступно после выбора записи. Эти же действия работают в собственных правилах исполнения и в форме комплекта.

Для автомобиля указываются марка, модель, необязательное поколение/кузов, название в списке и необязательные годы выпуска. Название нового автомобиля предлагается из первых трёх полей и допускает ручную правку. Для модификации — название и примечание; родительский автомобиль задан текущим правилом.

Окно открывается поверх формы. Несохранённые название товара, цена, фотографии и правила остаются в форме. Сохранённая запись сразу появляется во всех списках. Новая запись выбирается в текущем правиле; сам товар затем сохраняется отдельным действием. Кнопки закрытия и сохранения остаются доступными при прокрутке длинного окна на телефоне.

**Справочник общий:** переименование и годы сразу используются магазином, независимо от публикации текущего товара. Окно показывает количество связанных карточек и сохранённых черновиков. Для другого автомобиля следует создавать новую запись, а не переименовывать прежнюю. Идентификаторы и адрес существующего автомобиля сохраняются; прежние условия совместимости не переписываются.

При выборе другого автомобиля сбрасывается модификация и статус становится «Не подтверждено». При выборе другой модификации также сбрасывается подтверждение. Годы, кондиционер и примечание остаются видимыми для проверки. Простое переименование той же записи не меняет статус. Неизвестные факты автоматически не заполняются.

## Серверный контракт

- GET `/api/manager/vehicles?kind=vehicle|version&id=<UUID>`: свежие данные записи, fingerprint, число связанных товаров/черновиков; только штатная сессия manager, `no-store`.
- POST того же маршрута: `action=save`, `kind`, `id`, `token` (null для новой записи), `data`, `idempotencyKey`. Штатные staff/Origin/CSRF, JSON до16КиБ. Марка/модель до100 символов, название до200, примечание модификации до2000; годы1970–2100 либо пустые.
- Миграция023 добавляет INSERT/UPDATE для ar_app на `ar_vehicles`/`ar_vehicle_versions` и таблицу `ar_vehicle_editor_events`. Удаление через новый API не предусмотрено; DELETE ar_app не выдаётся. Существующие строки и связи миграция не меняет.
- Сохранение транзакционно и идемпотентно. Короткая блокировка таблиц справочника сериализует запись с CMS; fingerprint защищает от перезаписи изменений из другой вкладки. Повтор после потерянного ответа возвращает тот же результат, не создавая вторую запись/событие.
- Названия проверяются без учёта регистра и повторных пробелов; модификации уникальны внутри автомобиля. Новый slug создаётся из названия, при занятом адресе получает суффикс ID; существующий slug не редактируется. Перенос существующей модификации к другому автомобилю запрещён сервером.
- История хранит автора, вид действия и снимки до/после; менять/удалять события роль ar_app не может. Это серверный аудит, отдельного экрана истории пока нет.
- Ответ сохранения содержит актуальные имена автомобилей/модификаций. Клиент обновляет только списки и выбранное правило, не перезагружает карточку товара. Редактирование справочника не пишет цены, остатки, галереи или подтверждения совместимости.

## Проверки

`tests/vehicle-editor.test.ts`: нормализация, годы, модификации и сброс подтверждения только при смене идентификатора. `tests/vehicle-editor-database.mjs`: отдельная `ar_qa_ai_images_vehicles_*`, полная схема; конкурентные повторы/дубли, старые токены/CMS, сохранность ID/URL/правил/черновиков/цен/склада, запрет смены родителя и удаления, неизменяемый аудит. Удаляет только созданную QA-базу.

`tests/vehicle-editor-browser.mjs`: отдельный local preview с настоящим API и фиктивной CMS;1440/768/375. Создание/редактирование/отмена, валидация, сохранность несохранённых полей, обновление всех списков, отдельное сохранение товара, клавиатурный фокус. Потеря ответа моделируется **после настоящего сохранения**; повтор проверяется с тем же ключом. Preview запускается через `tests/helpers/ai-image-preview.mjs` с уникальными БД/каталогом, simulation и worker off. Регрессия прежнего редактора — `tests/product-editor-browser.mjs`.

На рабочем сайте проверять вход/GET/окна/адаптивность без создания вымышленных автомобилей и без переименования действующих записей. Проверенные результаты — `artifacts/vehicle-editor/`; снимки и временные реквизиты QA только в private. Это не проверка фактической применимости товаров к новым автомобилям.
