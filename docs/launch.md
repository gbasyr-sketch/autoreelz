# Переход от тестовой витрины к реальным продажам

На24.09.2026 публичный staging уже размещён, ЮKassa sandbox и настоящий калькулятор СДЭК работают. Это не разрешение принимать реальные деньги, отправлять товары или внешние сообщения. [Текущее состояние](status.md) · [Очередь работ с критериями](backlog.md).

## Данные, которые уже получены

Сервер91.200.150.79/SSH/домен, Timeweb Pro, OIG, реквизиты ИП, тестовые ключи и HTTP-уведомления ЮKassa, договор/API СДЭК, MKHCH13/город442, Яндекс JS API, две выгрузки WB. Не запрашивать заново и не повторять initial-transfer. Рабочая БД находится на сервере.

## Необходимые результаты

| Направление | Текущее ограничение | Пункт очереди |
|---|---|---|
| Документы/контакты | Оферта/политики черновые, публичный контакт и адрес возвратов ещё не утверждены | B01/B10 |
| Чеки/налоги | Сервис кассы/ОФД и схема чеков не выбраны | B02 |
| Эквайринг | Только sandbox-карта; live, провайдерские возвраты и контролируемая проверка СБП не завершены | B03 |
| Доставка | Справочники/ПВЗ/курьерский тариф готовы, накладных/реальных отправлений нет | B04/B09 |
| Почта/MAX | Имитаторы, нет согласованных сервисов/получателей | B05 |
| Эксплуатация | Нет подтверждённой регулярной полной серверной/offsite-копии и restore-drill | B06 |
| Каталог | Первая партия30 карточек есть; остальные исполнения, точная применимость и составные упаковки не завершены | B07/B08/B09 |
| Индексация | noindex включён; реальные страницы/фид/замеры ещё требуют итоговой проверки | B11 |

## Порядок дальнейшей работы

1. Выбрать ограниченную задачу из backlog и закрыть её критерии в QA/sandbox. Не смешивать тестовые данные с рабочими заказами.
2. Для платёжных/доставочных/почтовых операций сохранить серверные снимки, идемпотентность, повторы и историю ошибок. Внешняя сеть не выполняется под складскими блокировками.
3. Согласовать реальные документы, чеки, контакты, возвраты и обработку данных. Аудит [legal-and-cookies-review.md](legal-and-cookies-review.md) датирован23.09.2026: перед запуском нормы проверяются заново.
4. Проверить совместный сценарий на конкретном SHA и конфигурации, подготовить совместимый откат/backup. Показать владельцу проверяемый результат и оставшиеся ограничения.
5. Только после отдельного поручения включать реальные деньги/отправления/внешние сообщения и, отдельно, индексацию.

`STORE_MODE=production` сейчас намеренно блокируется тестовыми API/worker. Смена флага не является реализацией реального магазина. Не возвращать общий пароль публичной витрины под видом подготовки к запуску.

Детальные технические контракты: [ЮKassa](yookassa-checkout-contract.md), [СДЭК](cdek-checkout-contract.md), [архитектура](architecture.md). Серверные команды — [server-staging.md](server-staging.md).
