# Приёмка этапа 3

21.09.2026. Новый проект autoreelz2026-new. Проверены PostgreSQL 17.11, Directus 12.3.1 и Astro SSR на Node 24.21.0 в Docker, архитектура arm64. Старые сервисы не использовались и не изменялись.

## Проверено и прошло

- Образы закреплены digest. Витрина собирается с npm 11.19.1 и lockfile, работает от пользователя node на read-only filesystem. Docker-контекст исключает .env, базы, исходные PDF и локальные инструменты.
- Сервисы db/cms/web healthy; db-init завершён с кодом 0. Порты 65432/28055/14323 привязаны к localhost, собственные сеть и тома.
- Fresh bootstrap в отдельном временном Compose-проекте: пустые тома, создание SQL-ролей и admin, вход HTTP 200. Временные контейнеры/тома/сеть удалены. [Результат](../artifacts/stage-3/bootstrap-check.json).
- Повторный setup-local --seed-demo прошёл: три применённые миграции пропущены по совпадающим SHA-256; новые записи не добавлены; существующие каталог и остатки сохранены. Метаданные CMS экспортированы без аккаунтов/секретов.
- 41 SQL-проверка в отдельной ar_qa_* копии новой БД. Проверены глубина/циклы категорий, артикулы, вид товара/SKU, типы и принадлежность значений, правила совместимости, наследование фото/характеристик, производные цена/остаток комплекта, история slug и SQL-права. Реальные конкурентные сценарии: смена вида товара против создания SKU в двух порядках и переименование против захвата старого slug. Временная БД удалена. [Результат](../artifacts/stage-3/schema-check.json).
- 7 групп API-проверок: отсутствие публичных прав, отказ анонимному CRUD каталога/склада/несуществующего будущего endpoint заказов, доступ редактора к каталогу/отношениям, отказ в записи склада и администрировании ролей/схемы, UUID полей ID и текстовые типы артикулов/slug. Таблицы заказов пока не созданы. [Результат](../artifacts/stage-3/permissions-check.json).
- Реальный браузер, Chrome 153 + Playwright 1.62.1: администратор и контент-менеджер. Для каждой роли: список → открыть товар → изменить → сохранить → вернуться к списку → открыть снова и проверить значение. Затем через UI созданы и повторно открыты товар, SKU, правило совместимости, комплект и его компонент. Проверочные записи удалены. [Результат](../artifacts/stage-3/browser-check.json).

## Исправлено до завершения

- Инициализация ролей вынесена в отдельный idempotent db-init: bind-mounted shell на macOS не должен зависеть от executable-флага.
- Технические email приведены к валидному example.com-поддомену; первичный вход проверен с нуля.
- Ссылки в списках CMS показывают названия вместо UUID, значения статусов переведены, вспомогательные таблицы скрыты из основного меню.
- Directus создаёт UUID ещё при открытии новой формы. Условие readonly по наличию ID ошибочно блокировало выбор товара для нового SKU; оно удалено. Неизменность владельца после сохранения обеспечивает SQL-ограничение и пояснение поля.
- Исправлены проверки общего триггера для разных таблиц; добавлены блокировки родителей, защита справочников и отдельный уникальный реестр текущих/исторических slug.
- Редактору разрешено удалять промежуточные связи, чтобы можно было исправлять составы и фотографии, сохранив запрет записи склада/ролей.
- Новая CMS получила собственные cookie names, не пересекающиеся с другими Directus на localhost.

## Что не входит в этот этап

Витрина ещё не читает CMS. Не реализованы заказы, серверная корзина, резервирование, тестовая оплата/доставка, OTP и торговые команды. Общий склад моделируется и проверяется, но ежедневные корректировки через безопасные команды появятся на следующем этапе. Полный аудит безопасности загрузок отзывов, SEO, реальные интеграции и приёмка продаж — последующие этапы.

Directus показал запрос реального владельца и принятия условий; использовано Remind Later. Юридические условия/грант/платный тариф не принимались от имени пользователя. Перед реальным запуском этот вопрос и лицензионные ограничения должны быть закрыты владельцем.
