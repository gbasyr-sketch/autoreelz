## Первый опубликованный вариант025

- В manager в карточке заказа — полный возврат конкретного подтверждённого платежа ЮKassa, включая доставку. Нужны причина, явное подтверждение и точная сумма из серверного снимка. Частичные возвраты и автоматическое разрешение спорного заказа пока не входят в эту версию.
- Только `yookassa-sandbox`, `local-test`/согласованный `staging`. Перед POST проверяются `/me` (свой account, test=true, фискализация выключена) и оплаченный исходный платёж. Любая накладная СДЭК, кроме rejected/cancelled, блокирует постановку возврата, в том числе уже исполненная. Отмена доступна только до передачи; после исполнения нужен отдельный безопасный разбор, в текущей версии он не реализован. Не удалять накладную и не подменять её состояние ради обхода блока.
- Одна неизменяемая запись `ar_yookassa_refunds` на платёж. Причина, сотрудник, сумма, магазин, ID платежа и ключ провайдера сохраняются до сети. Разные клиенты/ключи не создают второй возврат. После canceled/attention новая попытка сама не появляется — нужна отдельная сверка/доработка ручного восстановления.
- Заказ переводится в manual_review/payment review при постановке запроса. Сборка/новая отправка блокируются общим порядком блокировки заказа. Сеть выполняется вне транзакции; lease90секунд. Физический склад и allocation_state не изменяются, даже после успешного возврата: наличие товара подтверждается отдельно. Разбор/закрытие заказа после возврата остаются ручной операционной задачей, автоматического «заказ полностью закрыт» нет.
- После таймаута/500 повторяются прежние тело и ключ; после23часов от первого запроса без provider ID — attention, новый POST запрещён. Известный ID сверяется через GET. Устаревший worker не перезаписывает результат новой lease. Неверные сумма/ID/валюта переводят попытку в attention.
- `refund.succeeded` на существующем webhook — лишь повод для GET. Неизвестный ID игнорируется, worker обеспечивает сверку без подписки на новый event. Объект возврата не содержит test/account: проверяется связанный платёж. История доступна при выключенном провайдере; исходные provider payload/контакты не возвращаются в DTO.
- Денежный успех возврата и чек — разные результаты. Фискальные чеки эта версия не формирует. При подключении «Чеков от ЮKassa» текущий предохранитель фискализации нельзя просто удалить: сначала необходимы снимки чеков и проверка их регистрации.
