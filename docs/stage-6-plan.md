# Этап 6 — полная локальная приёмка

Владелец разрешил этап 6. Основа — бриф, сценарии промпта6 и new-store-kit/06-seo-plan.md. Следующий реальный запуск/интеграции отдельно. Текущая среда остаётся noindex и loopback; лицензия и прежние проекты не меняются.

## Работа и области

- Главный: SEO-политика/canonical, JSON-LD, sitemap/YML, SSR-пагинация и slug-редиректы, необходимые новые поля видео, интеграция и итоговая матрица. Владеет Layout/middleware/pages/core schema.
- Независимая проверка торговли: аудит прав/гонок/сумм/истории, соответствие обязательным сценариям и прогон профильных PostgreSQL-наборов. Найденные дефекты сообщать главному, не менять общий код параллельно.
- Мобильный интерфейс: UI/UX Pro Max, клавиатура/фокус/пустые состояния, воспроизводимые лабораторные измерения. Файлы измерений и при необходимости только fonts/CSS по согласованию; Layout не менять самостоятельно.
- CMS-аудит: создание/перенос трёх уровней категорий через новую CMS и наблюдение навигации/фильтров/публикации. Только помеченные QA записи с cleanup и отдельная тестовая БД для опасных проверок.

## SEO-контракт

Публичный origin фиксируется как https://autoreelz.ru. Локально meta и HTTP всегда noindex, robots Disallow:/, sitemap/товарный фид не включают тестовые записи. Публичные правила готовятся и тестируются отдельно: включение возможно только явным флагом и production mode/HTTPS-origin, не через query/header. В этой сессии публикацию/индексацию не включать.

Canonical: базовая карточка для sku/подбора, self URL с page=N для существующей пагинации. Поиск/фильтры/сортировки/private/errors/draft/demo — noindex; утилитарные query не попадают в sitemap. Category сохраняет свой query category=slug как существующий маршрут. Каталог: страницы по12 товаров, реальные HTML-ссылки, page1 нормализован, неизвестный category и отсутствующая page —404; пустой поиск page1 —200.

JSON-LD только SSR и факты: Product/Offer, ProductGroup для реальных вариантов, BreadcrumbList, Article. Никаких rating/aggregateRating, выдуманных GTIN/брендов/сроков доставки. Фото-заглушки и демоданные не выдавать за реальную продукцию в экспортах. Для VideoObject нужны собственные проверенные название/описание/превью/uploadDate; при отсутствии данных разметку не создавать. Плеер по согласию, но текст/ссылка/превью видны в HTML.

301 старого product/category slug через существующий registry, только на актуальную опубликованную сущность, без цепочек и редиректа на главную. Не подменять неизвестный SKU дефолтным.

Экспорты — чистые функции + HTTP endpoints. Рабочий local-test не предоставляет indexable sitemap или реальный merchant feed; валидные XML/JSON и публичная allowlist проверяются на явных QA fixtures. Фид в RUB согласован с конкретным SKU/комплектом, предзаказ и неизвестная доставка не получают выдуманных сроков.

## Проверки и отчёт

Сопоставить каждый пункт промпта6 с доказательством. Новые ошибки исправить и проверить регрессией; успешные проверки повторять только после затрагивающих изменений. QA endpoints/базы/порты изолированы, licensed Directus на копиях не запускать. Тяжёлую Docker-сборку не совмещать с mobile measurements/критичными CMS E2E.

Финальный отчёт: прошло, исправлено, не проверено, до реальных продаж. Lighthouse/TBT не выдавать за полевой INP, указать Chromium/Lighthouse версии, viewport/throttling/cache/число запусков и медиану. Внешние валидаторы не считать пройденными без реального результата; localhost не публиковать ради валидатора.
