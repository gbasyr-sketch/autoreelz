## Размещение

Сервер Ubuntu22.04.5 x86_64,4CPU/8ГБ RAM/79ГБ диск (54ГБ свободно при проверке), ISPmanager. Nginx/Apache/почта уже работают. Для нового магазина создан отдельный пользователь `autoreelz2026` (UID1018), каталог `/srv/autoreelz2026` и rootless Docker29.8.1 с cgroupv2. Compose5.5.1 и Buildx0.37.1 установлены только этому пользователю; бинарники проверены по опубликованным SHA256. Из apt добавлены только uidmap/slirp4netns/libslirp0, без обновлений/удалений прежних пакетов и перезапуска прежних служб.

Compose-проект `autoreelz2026-release`, файлы `infra/release/compose.yaml` + `ispmanager.yaml`. Edge слушает только127.0.0.1:14324, внешний HTTPS остаётся за Nginx. Витрина защищена отдельным паролем. `/cms/admin` обслуживает Directus с собственным входом: двойной Basic Auth мешает Bearer API Studio, поэтому для `/cms/*` используется штатная авторизация CMS. БД/CMS/web не публикуют отдельные порты.

`STORE_MODE=staging` разрешает только тестовые адаптеры на точном HTTPS-origin `https://autoreelz.ru`; production по-прежнему их блокирует. Поиск закрыт от индексации даже при случайном SEO_INDEXING_ENABLED=true. Базовая покупка на сервере сначала остаётся имитацией; ЮKassa ещё не подключена к checkout, ключей тестового магазина нет.

## Данные и доступы

Согласованная копия берётся только из нового локального проекта. `scripts/prepare-staging-copy.mjs` работает с удаляемой QA-базой: сохраняет каталог/контент/CMS-метаданные, очищает сессии/OTP/тестовые заказы/активность, меняет пароли сотрудников и отключает старую лицензионную привязку в копии. Локальная БД не меняется. Все новые секреты, TLS и файлы доступа остаются в private и вне Git.

Локальный архив переноса: `private/staging-transfer-2026-09-23T15-04-22-391Z/`. Новая привязка OIG — `https://autoreelz.ru/cms`; исходная локальная лицензия не деактивируется. На сервере ключ применять только к новому Directus, без повторной активации одноразовых клонов.

## Переключение и откат

Для сайта меняется только vhost `/etc/nginx/vhosts/autoreelz/autoreelz.ru.conf`, с отдельной копией до изменения. Старые файлы сайта/БД/службы не удаляются. Перед reload — nginx -t; после — проверка HTTPS, авторизации, Studio, health SHA, worker и прав. При ошибке вернуть сохранённый vhost и reload. Изменение TLS относится только к autoreelz.ru; другие сертификаты не трогать. ISPmanager может перегенерировать ручной vhost: учитывать это при будущих изменениях домена через панель.

Статус на момент подготовки документа: локальные проверки staging прошли, сборка/перенос/переключение ещё выполняются. Итоговый SHA, серверный image ID и результаты будут зафиксированы после фактического запуска.
