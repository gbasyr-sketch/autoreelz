# Интеграции этапа 5

Проверено по официальным источникам 22.09.2026. На этом этапе работают только локальные адаптеры. Наличие описанного API не означает подключение аккаунта или разрешение отправлять реальные данные.

## Описание товара

Кнопка в карточке товара Directus открывает кабинет владельца. Сервер готовит два текста по явному набору фактов: название/категория, исполнения и артикулы, состав и заданные характеристики, отметка демоданных. Персональные данные покупателей и ручной SEO-title в адаптер не передаются. Неизвестная совместимость не превращается в утверждение «подходит».

Сейчас `adapters/description.ts` — детерминированный имитатор, стоимость вызовов нулевая. Preview не меняет товар. Apply проверяет сотрудника, хеш актуальных исходных данных и прежних текстов, затем обновляет только description/meta_description. Ошибка провайдера или конфликт сохраняют прежнюю карточку.

Для будущего OpenAI-адаптера подходит Responses API со Structured Outputs: строгий объект с двумя строками description/meta_description, запрет дополнительных полей, обработка отказа/обрезанного ответа и повторная серверная валидация. Секрет — только на сервере. Модель и оплачиваемый доступ пока не выбраны.

Предложение до отдельного подключения: общий бюджет $5 в месяц, до 100 генераций в день, до 2000 выходных токенов на запрос; фактический лимит денег рассчитывать по выбранной модели и её актуальному тарифу, с резервированием бюджета перед запросом. Это предложение, не включённая платная функция. В текущем имитаторе действует ограничение 20 новых попыток в час на сотрудника; повтор успешной команды возвращает сохранённый результат.

Текст должен помогать выбору товара, соответствовать фактам и проходить редактуру. Нет обещаний позиций в поиске или «нераспознаваемости ИИ». Источники: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Google о генеративном контенте](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content), [Яндекс: малополезный контент](https://yandex.ru/support/webmaster/ru/threat/useless-content).

## MAX и email владельца

Официальный MAX Bot API поддерживает POST /messages, получателя user_id либо chat_id и токен в заголовке Authorization. На дату проверки документация указывает platform-api2.max.ru и отдельное требование к доверенным сертификатам; перед реальным подключением нужно проверить актуальную цепочку доверия. TLS-проверку не отключать. Ограничение отправки — до двух сообщений в секунду одному получателю.

В проекте `ar_owner_notifications` создаётся транзакционно из событий заказа, по уникальной паре event_key/channel. Worker обрабатывает записи через локальный адаптер и показывает результаты в кабинете владельца. Повтор тика не повторяет доставку, ошибка сохраняется; ручной retry ограничен тремя попытками. Статус «доставлено» здесь означает только обработку имитатором.

Для реального запуска нужны бот, проверенный токен, получатель MAX, отдельно подтверждённый email для уведомлений и email-провайдер. Email, предоставленный для заявки OIG, автоматически получателем уведомлений не назначается. Содержимое реального сообщения следует ограничить номером заказа, типом события и защищённой ссылкой, без адреса и телефона покупателя. Источники: [обзор MAX API](https://dev.max.ru/docs-api), [отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages).

## Доставка и CRM

Локальный имитатор перевозчика подписывает событие и передаёт его общему обработчику. Подпись, ID/хеш события, время и порядок статусов проверяются. При ручном override событие остаётся в истории, но публичный статус не меняется. Явное снятие override применяет последнее допустимое состояние и трек перевозчика. Реальный СДЭК-адаптер и его схема подписей/событий подключаются отдельно.

Источник истины — PostgreSQL AUTO REELZ. Будущая внешняя CRM, например Битрикс24, получает события с устойчивыми ID; импортированное действие должно иметь собственный ключ идемпотентности и проверенного сотрудника. Прямой внешний CRUD склада и перезапись снимка заказа не разрешаются. Токены и соединение с CRM не настроены.
