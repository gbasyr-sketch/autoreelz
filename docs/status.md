# Состояние AUTO REELZ

Обновлено 21.09.2026. Этап 2 завершён: выбранное направление A реализовано в Astro на демонстрационных данных. Следующий этап — 3a/3b: изолированная среда Docker, PostgreSQL, Directus и каталог в CMS. Инфраструктура и реальные торговые операции пока не запускались.

## Готово

- Утверждённая дизайн-система: [MASTER.md](../design-system/MASTER.md).
- Astro SSR: главная, каталог и товар. Поиск по названию/артикулу, категории, сортировка, применимые фильтры, выбранные условия и их удаление.
- Прямой URL исполнения сразу возвращает нужные цену/наличие в серверном HTML. Фильтры и поиск по артикулу относятся к одному SKU.
- 8 демонстрационных товаров, в том числе 2 фиксированных комплекта. Данные владельца не заменяются этими fixtures; артикулы имеют префикс DEMO.
- Мобильные меню/поиск/фильтры, галерея, количество, избранное и демонстрационная корзина. Сохранение только в текущем браузере, без заказов и складских операций.
- Состояния предзаказа, неизвестной совместимости, пустого поиска/фильтра, неверной цены/количества, 404 товара/исполнения и ошибки браузерного хранилища.
- Шрифты локальные, SVG-экспорты исходных PDF и подписанные заглушки. Оригинальный бриф/материалы не изменены.

Локальная витрина: http://127.0.0.1:14322/. Архив сравнения прототипов: http://127.0.0.1:14321/. Запуск и маршруты проверки — [development.md](development.md).

## Проверки

- Node 24.21.0 установлен только в игнорируемую .tools; официальный архив проверен по SHA-256. Глобальный Node не заменялся.
- Исправлена несовместимость подготовительного TypeScript 7 с @astrojs/check: закреплены TypeScript 6.0.3 и checker 0.9.10, lockfile обновлён.
- `npm run check`: 0 ошибок/предупреждений; `npm test`: 7 проверок; `npm run build`: успешная standalone SSR-сборка.
- Главная/каталог/товар проверены в Chrome через Playwright на 375/768/1024/1440 px. Нет горизонтального переполнения, JS-ошибок и внешних запросов страниц.
- Проверены 18 основных браузерных сценариев, отдельно повторно проверены исправленный поиск по артикулу и мобильная панель фильтров. SSR вариантов и фильтры проверены с отключённым JS.
- Независимое чтение кода выявило выбор неправильного SKU при поиске по артикулу; исправлено и закреплено регрессионной проверкой. Повторные точечные проверки прошли.
- Отчёт и снимки: [stage-2-review.md](stage-2-review.md), artifacts/stage-2.

Это проверка витрины на fixtures, не приёмка торговли. CMS/БД, платежи, доставка API, OTP, реальные статусы заказов, защита торговых транзакций и полные SEO/производительные проверки остаются будущими этапами.

## Подтверждённые решения

Направление A; временные заглушки; при частичной нехватке целая строка в предзаказ; при конкуренции строк порядок добавления с показом разделения до подтверждения. Бриф сохраняет приоритет. Подробности: [decisions.md](decisions.md).

Docker предназначен для новой изолированной среды; старые контейнеры/базы/подключения не изменялись. Текущий Directus MCP не использовать. У владельца есть GitHub-репозиторий; адрес пока не передан, remote отсутствует.

## Что потребуется дальше

1. Для наполнения: реальные SKU/артикулы, цены/остатки, составы, годы/модификации/кондиционер, материалы, фотографии, упаковка/коробки. Не выдумывать совместимость; пока она неизвестна.
2. До реальных продаж: эквайринг/чеки, СДЭК, реквизиты ИП, email/MAX, сервер, лицензия Directus и адрес GitHub.
3. До платной генерации: модель, бюджет и проверенные входные поля.

Не спрашивать повторно выбранный дизайн, домен, розницу, палитру, заглушки и согласованные правила предзаказа. Следующий этап выполнять отдельно по плану; не переходить сразу к полной торговле/публикации.
