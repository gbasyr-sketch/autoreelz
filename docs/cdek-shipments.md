## Подтверждённый процесс15.10.2026

Владелец сам отвозит посылки в рабочий ПВЗ MKHCH13, Махачкала, пр-т Петра Первого,83. Забор курьером не нужен. Размеры упаковок на сайте подтверждены владельцем; используем сохранённую в заказе упаковку, без повторного сбора размеров каталога. Для нескольких товаров применяется подтверждённая упаковка всего состава: если её нет, сохраняется ручное уточнение, отдельные коробки не считаются автоматически общей.

Объявленная стоимость — полная фактическая стоимость товаров оплаченного заказа, с количеством и ценой комплекта, без стоимости доставки. Она уже вычисляется сервером из неизменяемого состава; скидка, включённая в цену покупки, не отменяется. Дополнительных сборов с получателя нет: товары и доставка оплачены магазину. Условия/сумма страхования по рабочему договору ещё не проверены; отдельную платную услугу не подключали.

Текущий интерфейс подставляет размеры/полный вес посылки из shipping_package заказа, если он сохранён. Вес одной единицы каждой позиции (для комплекта — всего комплекта без внешней коробки) сотрудник указывает при подготовке; он не выводится из габаритов и не выдумывается.

## Работа владельца

В карточке оплаченного заказа `/manager/orders/{id}` появляется блок «Отправление СДЭК».

1. Проверить одну коробку: вес с упаковкой в граммах и размеры в миллиметрах. Из заказа подставляется сохранённая упаковка; неизвестные размеры остаются пустыми. Для каждого товара указать фактический вес одной единицы, для комплекта — всего комплекта без внешней коробки. Суммарный вес товаров не может превышать вес посылки.
2. Нажать «Проверить посылку». Сервер проверяет оплату, состав/суммы, направление и пригодность ПВЗ; показывает получателя, пункт отправления/назначение, тариф136/137, размеры с округлением вверх до см и объявленную стоимость.
3. Подтвердить создание. Получателю к оплате в СДЭК —0: товары и доставка уже оплачены магазину. Объявленная стоимость равна стоимости позиций заказа; от неё СДЭК рассчитывает страховку. Стоимость услуг перевозчика по договору не переопределяет оплаченную покупателем сумму. Проверка ПВЗ не является новым расчётом тарифа.
4. Дождаться регистрации. Страница может быть закрыта: запрос и результат находятся в БД. Номер СДЭК появляется после подтверждения. Создание накладной не означает передачу посылки перевозчику.
5. «Сформировать накладную PDF» → «Скачать накладную». Файл доступен только сотруднику. Ссылка ограничена по времени; после истечения можно сформировать новый PDF без нового отправления.
6. До передачи посылки можно запросить отмену, указав причину. Отмена окончательна после REMOVED либо после принятого СДЭК запроса DELETE и подтверждённого отсутствия накладной по UUID и номеру магазина. Она не отменяет заказ/оплату и не возвращает товары на склад.

История показывает запросы, подтверждения и ошибки. Состояние незавершённых действий обновляется на открытой странице каждые10секунд, если пользователь не редактирует форму; есть ручное обновление. Для ручной корректировки статуса сохранены прежние инструменты заказа. Действующий ручной статус не перезаписывается перевозчиком; «возобновить статусы перевозчика» применяет последнее подтверждённое событие.

## Границы первой версии

- Одна посылка на один оплаченный заказ. После объединения checkout15.10 весь смешанный состав остаётся в одном заказе и подтверждается менеджером до оплаты. Состав комплекта передаётся как купленная позиция с фактической ценой комплекта; его склад не списывается заново.
- Нет автоматического подбора коробок, наложенного платежа, дополнительных платных услуг, вызова курьера на забор и создания возвратной накладной.
- Поддерживаются заказы с сохранёнными кодами города и ПВЗ/курьерским адресом СДЭК. При ручном адресе без кодов интерфейс предлагает оформить накладную в кабинете СДЭК и внести трек через прежние инструменты.
- Статусы поступают через авторизованный GET API и сохраняются как события. Публичный webhook не добавляется. CREATED означает подготовку, приём/движение груза — отправку, DELIVERED/POSTOMAT_RECEIVED — получение. NOT_DELIVERED/неизвестный статус требует решения, не означает успешную доставку.
- Тестовое подключение заменяет имя/телефон и курьерский адрес синтетическими значениями; email покупателя не передаётся. Тестовые статусы не меняют доставку заказа магазина, не открывают право на отзыв и не превращают тестовую доставку в реальную.

## Надёжность и доступ

`ar_cdek_shipments` сохраняет неизменяемые получателя, состав, упаковку, среду/аккаунт и случайный уникальный внешний номер. `ar_cdek_prints` — отдельные задания печати; `ar_cdek_history` — неизменяемая история. Ни CMS, ни покупатель доступа к таблицам не получают. Штатные staff/CSRF/Origin и приватный no-store применяются ко всему manager API/PDF.

Создание атомарно и идемпотентно: команда с тем же ключом возвращает прежний результат; одновременно разрешено одно активное отправление на заказ. Короткая транзакция READ COMMITTED блокирует заказ перед проверкой существующего отправления, поэтому запрос с новым ключом тоже не создаёт дубль. Подтверждение предпросмотра связано с точным составом/ценами/упаковкой/аккаунтом и действует5минут.

Worker фиксирует отправку запроса **до** сети. Два worker не исполняют одну операцию благодаря lease90секунд и проверке его ID при записи. SQL-блокировки не держатся во время API. После таймаута, сбоя или перезапуска POST не повторяется: GET ищет отправление по UUID или неизменяемому номеру. Ответ «не найдено» не доказывает отсутствие первой операции и не разрешает повторный POST. После DELETE документированные `v2_entity_not_found` и `v2_entity_not_found_im_number` могут означать удаление. Они завершают отмену только после сохранённого принятия DELETE, паузы не менее30секунд и проверок UUID/номера в том же аккаунте. Обычный HTTP404/ошибка поиска не служит таким доказательством. Неопределённость остаётся видимой до сверки с СДЭК; автоматического сброса нет. После доказанного отклонения/отмены новая попытка получает новый номер, старая история сохраняется.

Подтверждение создания опрашивается раз в минуту, обычные статусы — раз в15минут, терминальные — раз в сутки; ошибки дают паузу5минут. Ручное обновление не обходит30секундную задержку. Ответы ограничены2МБ, PDF16МБ и сигнатурой `%PDF-`, запросы15секундами. Неизвестный исход печати не повторяется автоматически; сотрудник может явно сформировать новый PDF, без создания второй накладной.
