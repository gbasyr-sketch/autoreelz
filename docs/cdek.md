## Подключение к checkout — опубликовано

Реализованы справочники города/ПВЗ, точные тарифы136/137 через calculator/tariff и снимок согласованной суммы в каждом заказе. Клиентская сумма не используется.

По присланному владельцем примеру добавлены два radio-способа СДЭК, интерактивная карта Leaflet/OpenStreetMap, группировка маркеров, поиск и согласованный выбор в списке/на карте. Leaflet и стили собраны локально, подложка загружается из tile.openstreetmap.org только для видимой карты с атрибуцией; массового скачивания нет.

## Стоимость при выборе пункта

По последнему уточнению владельца цена и общий итог появляются сразу при выборе ПВЗ (или после ввода адреса курьера), ещё до контактов и шага подтверждения. Серверный delivery-estimate не сохраняет заказ/checkout-quote и не резервирует склад. Смена пункта очищает старую сумму, запросы задержаны на400мс, старые ответы не применяются; по5минутам расчёт нужно обновить. Ошибка/неизвестная упаковка отображается «Уточнит менеджер», без нулевой вымышленной цены.

Публичный тест на a908f83: MSK2/MSK3 Москва390₽, курьер640₽, выбранный владельцем MKHCH13 в Махачкале185₽ (итого1985₽). Контакты не заполнены, заказов0. Проверка специально отключала SDK карты в тестовом браузере и подтвердила независимость списка/тарифов. Источник — artifacts/cdek-checkout/public-estimate-check.json. Яндекс.Карты остаются выбранным картографическим сервисом; экспериментальный callback-loader из диагностики не публиковался.
