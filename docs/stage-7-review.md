# Этап 7 — текущий результат подготовки

23.09.2026. **Этап начат, целиком не завершён.** Серверная тестовая версия опубликована на основном autoreelz.ru по отдельному поручению владельца. Выбрана ЮKassa, договор СДЭК есть; реальные API и деньги ещё не подключены. Ниже подготовка и результаты; ветка `codex/stage7-launch-prep`.

## Проверено

- Согласованная локальная копия новой БД/ролей/секретов/uploads. Остановлены и возвращены только web/worker/CMS нового проекта; копия заняла 17 секунд и осталась в private.
- Восстановление в отдельном PostgreSQL17.11 без сети/host-портов/Directus: **85 таблиц, 5850 строк, 2 файла** совпали, ключевые SQL-права сохранились. Drill занял 11 секунд; контейнер, его том и временные файлы удалены. [Результат](../artifacts/stage-7/restore-drill.json).
- Повреждённый дамп, внешний путь, выход через symlink и параллельный backup отклоняются до опасной операции. [Отрицательные проверки](../artifacts/stage-7/restore-guards.json).
- Read-only monitoring: четыре healthy-сервиса, свежий heartbeat/копия, нет просроченных выделений, manual_review и проблемных очередей на момент проверки. [Отчёт](../artifacts/stage-7/ops-check.json).
- Compose отдельного будущего сервера и Caddy2.11.4 валидированы с фиктивными значениями и отключённой сетью. Публичный сертификат не выпускался, сервер не запускался. БД/web/worker без host-портов, CMS loopback-only, SEO выключен. [Проверка конфигурации](../artifacts/stage-7/release-config.json).
- **5 HTTP-групп** на QA-клоне: revision в health, Secure/HttpOnly/SameSite cookie за HTTPS-прокси, нормальная CSRF-проверка, запрет чужого forwarded host/Origin, невозможность использовать локальные payment/mail-имитаторы в production. Это не внешний TLS-тест и не готовая production-покупка. [Результат](../artifacts/stage-7/proxy-check.json).
- **56 быстрых тестов**, 6 интеграционных наборов пропущены стандартной командой; целевая браузерная регрессия покупки **9/9 групп** после изменения proxy-конфигурации прошла, QA-база удалена. Astro check: **83 файла**, 0 диагностик; SSR-сборка успешна.

Отдельный клиент ЮKassa прошёл **9 групп на HTTP-фикстурах**, включённых в быстрые тесты. Проверены test-shop, точные RUB, одинаковый ключ повтора, проверка статуса через GET, отказ несогласованной фискализации и обработка неизвестного исхода. Он пока не подключён к checkout/webhook; никаких реальных запросов к ЮKassa не выполнялось. Ключи — только в private/yookassa-sandbox.env. См. [yookassa.md](yookassa.md).

В Docker добавлены полный APP_REVISION и OCI-label; `/health` показывает проверяемую ревизию без секретов/частных метрик. `build-release.mjs` собирает только чистый commit и сохраняет manifest в private/releases. Это сборка, не публикация; версию после локального запуска сверяют с SHA образа.

## Обнаружено при подготовке

В первой репетиции готовность PostgreSQL определялась по временному socket-only серверу и восстановление стартовало до завершения init. Проверка изменена на TCP readiness; повторный drill прошёл полностью. Первая предпосылка HTTP-теста ожидала изменение корзины в production, хотя текущая версия намеренно блокирует все торговые POST вне local-test; тест исправлен на независимую проверку Origin/CSRF через social endpoint. Защита имитаторов не снималась.

Аудит наполнения: **4 опубликованных товара, все демонстрационные; 7 SKU, у всех отсутствует упаковка; 0 правил упаковки; 4 опубликованных юридических проекта**. Две строки совместимости в демокаталоге не подтверждают фактическую применимость для продаж. [Агрегаты](../artifacts/stage-7/readiness.json). Утверждение «упаковка внесена» пока не подтверждено БД.
