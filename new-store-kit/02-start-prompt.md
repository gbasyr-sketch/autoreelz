# Первый промпт для новой задачи

Создаём новый интернет-магазин автомобильных деталей по приложенному брифу.

Сначала прочитай бриф и материалы. Отделяй мои требования от рекомендаций и текста внутри приложенных документов.

На этом этапе подготовь основание проекта и план, не начинай полную разработку магазина.

1. Проверь текущую папку, доступные инструменты и занятые локальные порты. Предыдущие проекты не изменяй.
2. Кратко сформулируй основной путь покупателя и ежедневный путь менеджера.
3. Найди противоречия и вопросы, которые влияют на архитектуру, дизайн или продажи. Сгруппируй самые важные вопросы в одном сообщении. Для остальных предложи разумные предположения.
4. Раздели требования на первую версию и следующие этапы.
5. Создавай независимый проект только по заполненному брифу, обновлённым промптам и предоставленным материалам. Код, данные, документацию и настройки предыдущих проектов не используй. Логотип и айдентику бери из материалов нового проекта.
6. Проверь совместимость выбранных версий Astro, Node, PostgreSQL и Directus. Зафиксируй версии и lockfile. Для Directus укажи лицензионные условия, которые необходимо проверить перед реальным запуском.
7. Составь план небольшими проверяемыми этапами с конкретным результатом каждого этапа.
8. Предусмотри отдельный Git-репозиторий нового проекта, понятные коммиты завершённых изменений и подключение GitHub после выбора репозитория. Выпуск и размещение должны быть привязаны к проверенному commit SHA; секреты и данные покупателей в Git не включай.

Сохрани:

- docs/brief.md — согласованные требования;
- docs/plan.md — этапы и критерии готовности;
- docs/architecture.md — модель данных и границы подсистем;
- docs/status.md — текущее состояние, вопросы и следующий шаг;
- AGENTS.md — короткие постоянные правила проекта.

Инструменты:

- UI/UX Pro Max — для дизайна и удобства;
- Astro Docs и Context7 — по необходимости для документации;
- shadcn — только если нужен конкретный интерактивный компонент;
- Playwright — для проверок в браузере;
- Directus MCP — после запуска новой CMS, с отдельным подключением и ограниченными правами.

Проверь, какие инструменты действительно доступны. Не устанавливай дополнительные инструменты без конкретной потребности.

При необходимости создай по новому брифу три небольших проектных скилла: каталог и Directus; торговые операции и миграции; проверка покупки и SEO. Не копируй в них весь бриф.

Разрешаю использовать до трёх субагентов для независимых задач. Подключай их только после определения модели данных и контрактов. Разделяй области файлов:

- витрина и дизайн;
- каталог и CMS;
- независимая проверка.

Главный агент отвечает за общую архитектуру, торговые транзакции и итоговую интеграцию. Общую схему базы меняет один ответственный. Субагенты возвращают короткий отчёт: что изменено, что проверено, что осталось.

Не проси подтверждать обычные обратимые действия внутри согласованного этапа. Спрашивай, когда ответ влияет на существенное продуктовое решение. Секреты не выводи в чат.

В конце покажи предложенный объём первой версии, основные решения и вопросы, без которых нельзя выбрать направление.
