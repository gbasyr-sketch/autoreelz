## Передача ключей

Ключи хранятся в двух полях `private/yookassa-sandbox.env`: YOOKASSA_SHOP_ID и YOOKASSA_SECRET_KEY из **тестового магазина**. Файл с правами 0600, исключён из Git и не подхватывается витриной автоматически. Shop ID — Настройки → Магазин; ключ — Интеграция → Ключи API. Ключи не присылать в чат.

Проверка доступа без создания платежей:

```sh
node scripts/check-yookassa.ts
```

Это только GET /me: проверка доступов и test=true, без создания платежа. Если магазин настоящий или ID не совпадает, клиент откажется. Инструкция получения ключей — [формат взаимодействия ЮKassa](https://yookassa.ru/developers/using-api/interaction-format), пример test/account_id — [официальный SDK](https://github.com/yoomoney/yookassa-sdk-php/blob/master/docs/examples/01-configuration.md).

## Что уже реализовано и проверено

9 групп тестов с подменённым HTTP-транспортом: фиксированный HTTPS API, server-side Basic Auth, ограничение ответа/таймаут; GET /me до POST; отказ live/чужому магазину; создание тестового redirect-платежа **только картой** с точной строкой RUB, capture=true и неизменяемым ключом идемпотентности вызывающей стороны. Ссылка возврата ограничена карточкой соответствующего заказа, банковские реквизиты карты клиент не принимает.

Сверяются provider ID, shop ID, test, сумма/RUB и metadata локального заказа/платежа. Статус из callback не считается подтверждением: используется аутентифицированный GET платежа. 500/таймаут POST — неизвестный исход, без автоматической новой попытки/нового ключа; caller должен повторять тот же ключ/данные и сохранять состояние. Ответы/секреты не попадают в ошибки. Непроверенные redirect-хосты отклоняются.

Если тестовый магазин требует фискализацию, создание блокируется RECEIPT_SETUP_REQUIRED: налоговые поля и чек не выдумываются. Чеки и возвраты денег ещё не подключены.

Контракт подтверждён [банковской картой](https://yookassa.ru/developers/payment-acceptance/integration-scenarios/manual-integration/bank-card), [быстрым стартом](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start), [webhook-проверкой](https://yookassa.ru/developers/using-api/webhooks). Тесты — `tests/yookassa.test.ts`, результат входит в artifacts/stage-7/fast-tests.tap. Протокол проверен на фикстурах; отдельно GET /me выполнен с предоставленными ключами. 11 транзакционных сценариев на отдельной QA-базе — artifacts/yookassa/integration.json; регрессия торговли34 и менеджера16 также прошла.

## Дальнейшая интеграция

После серверного размещения проверить полный платёж официальной тестовой картой и GET статуса. Настроенный endpoint уведомлений: https://autoreelz.ru/api/payments/yookassa, события payment.succeeded и payment.canceled. Владелец сохранил его в личном кабинете тестового магазина ЮKassa. Worker также сверяет статус как резервный механизм. Настоящую доставку уведомления провайдером не считать проверенной по собственному HTTP-повтору.

API обеспечивает повторяемость ключа лишь 24 часа; после этого неопределённую операцию сначала разбирать/сверять, не пересоздавать автоматически. В текущем тестовом магазине доступны карта/ЮMoney; полный тест СБП может потребовать отдельного разрешённого реального платежа. Тестовая фискализация не выдаёт настоящий чек. Источники: [идемпотентность](https://yookassa.ru/developers/using-api/interaction-format), [ограничения тестирования](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing).

Чеки/онлайн-касса и налоговые параметры остаются открытыми. Реальные платежи, возвраты денег и отправка чеков не включены.
