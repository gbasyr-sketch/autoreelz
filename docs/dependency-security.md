## Quill: защита вместо фиктивного нулевого аудита

В первичном исследовании уязвимы HTML-экспорты формул и встроенного видео. Эти форматы не входят в наш контракт редактора. Полный импорт `quill` заменён на `quill/core` с явной регистрацией поддерживаемых заголовков, начертаний, списков, цитат, выравнивания, ссылок, фотографий, toolbar и Snow. Модули formula/video **не включены в граф браузерной сборки**, а не просто спрятаны кнопки. Отдельный видеоплеер VK/RUTUBE материала остаётся прежним.

Серверная safeRichHtml сохранена при нормализации, предпросмотре, сохранении/чтении и публичном выводе. Новая регрессия проверяет опасные формы экспорта на всех этих границах: обработчики событий/внешние изображения не проходят, обычный текст и безопасная ссылка сохраняются. Проверка реального entry редактора `tests/content-editor-bundle.mjs` подтверждает отсутствие полного Quill/formula/video и наличие10 используемых форматов.

Источники: [исследование CVE-2025-15056](https://fluidattacks.com/advisories/diomedes), [официальный модульный импорт](https://quilljs.com/docs/installation), [advisory без исправленной версии](https://github.com/advisories/GHSA-v3m3-f69x-jf25). При появлении поддерживаемого исправления вновь проверить редактор; оставшееся предупреждение не объявлять удалённым из библиотеки.

## Важное уточнение о кэшировании

Сопровождающий http-cache-semantics оспаривает исходный отчёт и закрыл issue: Set-Cookie сам по себе не запрещает HTTP-кэширование. Поэтому переход4.3.0 и исчезновение предупреждения **не выдаются за доказательство исправления конкретного сценария утечки**. Astro использует библиотеку для удалённых изображений и проверяет storable() перед сроком хранения; вызов satisfiesWithoutRevalidation() в этой цепочке не найден. Страницы/приватные API магазина сохраняют no-store, персональные ответы в общий кэш не помещаются. [Обсуждение сопровождающего](https://github.com/kornelski/http-cache-semantics/issues/56).
