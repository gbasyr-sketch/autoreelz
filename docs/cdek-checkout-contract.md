# СДЭК в оформлении заказа

Продолжение этапа7 по поручению владельца. Рабочий API используется только для справочников и калькулятора. Накладные, вызов курьера, реальные платежи и сообщения не создаются.

- SHIPPING_PROVIDER=simulation сохраняет локальную приёмку; cdek явно включается на staging. Ключи только в окружении web. Отправитель MKHCH13/город442. Обычная «Посылка»:136 до ПВЗ,137 до двери; недоступный тариф означает ручной расчёт, без автоматической замены на экспресс.
- Город выбирается из справочника РФ, ПВЗ — из того же города. Сервер заново проверяет коды, направление выдачи/приёма и пригодность выбранного ПВЗ для упаковки; адрес ПВЗ берётся у СДЭК. При сбое можно указать адрес вручную, стоимость останется неизвестной до решения менеджера.
- Пакет для одной физической штуки берётся из SKU. Несколько штук/комплект требуют точного packing-rule. В БД г/мм, для СДЭК г/см с округлением габарита вверх. Не складывать размеры предметов автоматически.
- Справочники и тариф запрашиваются вне SQL-транзакции. До и после сети проверяются корзина, цены, распределение обычный/предзаказ и упаковка. При оформлении под блокировками выполняется та же проверка, без повторного API-запроса. Подтверждённая сумма берётся из сохранённого серверного расчёта, не из браузера.
- Расчёт действует5минут. В каждом заказе сохраняются собственные упаковка, ПВЗ/адрес, код/название тарифа, точные рубли и сроки из ответа. Обычный заказ/предзаказ рассчитываются отдельно. Сбой/неизвестная упаковка не равны бесплатной доставке и блокируют оплату до ручного уточнения.
- total_sum/RUB выбранного тарифа — стоимость от API без самостоятельно добавленных платных услуг. Создание отправления и согласование дополнительных услуг остаются отдельной работой перед реальными отправками.
- Проверки: прямые протокольные фикстуры; изолированная БД — изменения во время сети, составы/упаковки, чужой/просроченный расчёт, повторы и отсутствие складских блокировок на время API; браузер mobile/desktop, реальный калькулятор и тестовая ЮKassa на сервере.

Источники: [официальная документация СДЭК](https://apidoc.cdek.ru/) через Context7, [официальный виджет](https://github.com/cdek-it/widget), [Astro server endpoints](https://docs.astro.build/en/guides/endpoints/#server-endpoints-api-routes). Для существующей формы применены UI/UX Pro Max: видимые подписи, состояния загрузки, сохранение фокуса и ручной путь при сбое.

Карта по присланному владельцем референсу: Leaflet1.9.4, маркеры/кластеры из координат СДЭК, поиск и синхронизация с кодом/адресом, резервный список. Подложка OpenStreetMap, атрибуция сохранена; только загрузка текущего viewport, без предварительного скачивания/офлайн-кеша. [Условия tiles](https://operations.osmfoundation.org/policies/tiles/). Карта грузится по выбору города, ключ платного картографического сервиса не нужен. При росте трафика выбрать подходящий tile-сервис; интерфейс выбора ПВЗ от карты не зависит.

Серверная проверка карты выявила закрытие popup при автоматическом pan: кластерные слои теперь перестраиваются только при zoom. Добавлена проверка сохранения popup после auto-pan. Справочники ограничены1000 записями в ответе и32 записями кеша, чтобы удерживать расход памяти web-контейнера.
