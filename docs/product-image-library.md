# Библиотека фотографий

03.10.2026 владелец попросил выбирать ранее загруженные фотографии и удалять ненужные. В форме обычного товара рядом с «Выбрать фотографии» добавлена **«Из библиотеки»**. Доступна и для общей галереи, и для собственных фото исполнения.

## Как пользоваться

1. Нажать «Из библиотеки». Поиск работает по названию фото, названию товара и артикулу связанного исполнения.
2. Выбрать несколько миниатюр, при необходимости перейти на следующую страницу. Выбор сохраняется между страницами и поиском. Уже добавленное в эту галерею фото отмечено; повторов нет. Общий предел —12 фотографий.
3. Нажать «Добавить выбранные». Фото добавляются в конец галереи, порядок и главное фото можно изменить обычными стрелками или перетаскиванием.
4. Сохранить черновик либо опубликовать товар. Выбор файла не копирует изображение и сам по себе не меняет витрину.

**«Убрать»** в галерее меняет только текущую форму. **«Удалить»** в библиотеке после подтверждения перемещает неиспользуемое фото в раздел «Удалённые». Оттуда можно нажать «Восстановить». Это обратимое удаление из списка, исходный файл остаётся на диске; автоматического окончательного удаления нет.

Снимок, используемый в товаре, исполнении, сохранённом черновике, рецепте инфографики или контенте, защищён. Архивные товары тоже учитываются. В текущей несохранённой форме удалить выбранные фотографии нельзя. Если фото удалили из другой вкладки до сохранения, форма предложит восстановить его или убрать ссылку; данные формы не теряются.

## Контракт

- GET `/api/manager/product-image-library?q=&page=1&scope=active|trash`: только `staff()`, no-store.24 результата на страницу, ограниченный запрос120 символов, стабильный порядок, уникальный fileId. `%` и `_` в поиске — буквальные символы, SQL параметризован.
- Библиотека содержит JPEG/PNG/WebP/AVIF/GIF из файлов CMS. SVG не предлагаются для нового выбора; прежние SVG галереи поддерживаются. Фотографии отзывов хранятся отдельно и в библиотеку не попадают.
- Миниатюры — существующий защищённый `/api/manager/product-image?id=…&thumbnail=1`,192×192 WebP. Расширено разрешение предпросмотра растровых файлов CMS для владельца, включая удалённые для восстановления. Публичный `/media` по-прежнему требует опубликованную связь.
- POST того же library endpoint: `{id, action:'trash'|'restore'}`; `staff()`, Origin/CSRF, лимит4096 байт. Повторы не создают записи повторно. `PHOTO_IN_USE`409 при использовании,404 для неизвестного/неподдерживаемого файла. Настоящее удаление через Directus не вызывается.
- Миграция016 добавляет только `ar_product_image_trash` (fileId, actorId, deletedAt), гранты SELECT/INSERT/DELETE роли приложения. Миграции001–015 не меняются.
- Короткая общая advisory-блокировка сериализует сохранение редактора с перемещением в корзину. Перед сохранением и публикацией проверяется существование/доступность выбранного файла; старый upload claim не разрешает вернуть удалённое фото в рецепт. Это не замена отдельным правилам прямого редактирования CMS.
- Диалог поддерживает клавиатуру/Escape, возврат фокуса, отмену выбора, ошибки/повтор, сброс приватного DOM при потере входа. В фоне заблокированы публикация, обновление и другие операции формы.
