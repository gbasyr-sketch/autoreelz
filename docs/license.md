## Хранение и управление

- Ключ и лицензионный токен сохранены штатным API в настройках новой БД Directus. В репозитории их нет. Приватная резервная копия ключа — `private/directus-oig-key.txt` (0600); папка исключена из Git.
- Лицензия управляется через Settings → License. LICENSE_KEY/ LICENSE_TOKEN в Compose не заданы, поэтому управление через Studio доступно.
- Экспорт схемы не содержит записи настроек или учётные данные; скрипт дополнительно отклоняет строки, похожие на лицензионный ключ.
- Принятые условия требуют телеметрию; в Compose явно включено TELEMETRY=true. Не отключать её при повторном setup.

## Привязка среды

Активация относится к этой базе проекта и PUBLIC_URL `http://127.0.0.1:28055`. Перезапуск того же контейнера/базы с тем же URL не требует новой заявки. Для production будет нужна соответствующая активация этого же проекта. Один ключ OIG предусматривает до пяти активаций для сред одного проекта.

До переноса существующей среды на другой PUBLIC_URL сначала штатно деактивировать старую привязку, затем изменить URL и активировать снова. Не удалять базу активированной среды без деактивации: можно потерять занятый слот.

Текущие QA-проверки создают только временные SQL-копии и сервер магазина, отдельный Directus на клонах не запускают. Не активировать ключ на одноразовых QA-средах и не публиковать их дампы: копии системных настроек могут содержать лицензионные секреты.

Онлайн-проверкам нужен доступ к licensing.directus.com. Согласно FAQ, после более семи дней без связи лицензия возвращается на Core; при превышении его лимитов возможна блокировка CMS. Это нужно учитывать в мониторинге production.

Источники: [управление лицензией и привязками](https://directus.com/docs/licensing/overview), [FAQ OIG](https://directus.com/oig/faq), [договор OIG](https://directus.com/terms/open-innovation-grant).
