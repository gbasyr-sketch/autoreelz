# Генерация описаний в форме товара

Обновлено14.10.2026. В обычном товаре доступны GPT-6 Luna и GPT-6.1 Sol через [выделенный шлюз](ai-gateway.md). Общий бюджет — **$10 в месяц**, включая проверки и правки; часовой квоты нет. Опубликованный SHA и модель по умолчанию — [status.md](status.md). DeepSeek выключен в выборе, прежние ключи и журнал сохранены. Комплекты пока не поддерживаются помощником.

## Как пользоваться

1. Откройте товар и заполните название, категорию, варианты и известные характеристики.
2. Раскройте «Помощник для описания». Выберите модель. Sol лучше сохранила полезные сведения в нашем небольшом сравнении; Luna дешевле. Это не гарантия качества каждого ответа.
3. В «Дополнительные факты о товаре» укажите проверенные сведения о материале, комплектности и установке. Противоречие единственного цвета в названии варианта/товара и характеристике «Цвет» останавливает запрос до оплаты. Цвет подсветки рассматривается отдельно. Такая проверка не обнаруживает все возможные противоречия.
4. Нажмите «Сгенерировать описание». Проверьте описание и meta description. SEO-заголовок генератор не изменяет.
5. Для правки заполните «Что изменить в этом варианте» либо используйте «Живее / Короче / Больше конкретики», затем «Переработать текст». Это **новый платный запрос**; предыдущий вариант сохраняется, даже если новый завершился ошибкой.
6. «Предыдущие варианты» показывает последние12 успешных запросов этого сотрудника по товару. Просмотр бесплатный. Можно открыть исходные заметки и явно подставить их обратно. При несовпадении текущих фактов применение блокируется; название, цены и другие поля товара из истории автоматически не возвращаются.
7. «Применить в черновик» переносит тексты только в форму. Затем отдельно сохраните черновик или опубликуйте товар.

Изменение фактов или ручных текстов во время генерации блокирует применение устаревшего ответа. После потери связи нажмите «Проверить результат запроса»: повтор использует прежние данные и ключ, не вызывает модель заново. Это работает и после обновления страницы в той же вкладке. «Сгенерировать другой вариант» означает новый оплачиваемый запрос. Неопределённый исход учитывается по верхней границе до проверки.

## Редакторский профиль2026-10-14.2

Тон — внимательный специалист магазина: естественные предложения, конкретные сведения, без рекламных превосходных степеней. Пять синтетических примеров показывают разные структуры по категориям. Название допускает грамматическую редактуру, но модели/поколения/размеры нельзя подменять. Для простого товара достаточно1–2 абзацев, для богатого фактами2–4; минимальной длины нет. Общая серверная концовка о совместимости удалена. Запрещены служебный пересказ и универсальные зачины вроде «добавляет цветовой акцент».

Сведения о комплектности, креплениях и необходимых доработках берутся из полей и дополнительных фактов. Обещания применимости требуют подтверждённых fitment-правил; пустое/unknown не становится compatible. Из notes не переносятся обещания долговечности, качества, универсальности и простоты установки. При конфликте важного свойства его нужно уточнить; источник-черновик правки не подтверждает новые свойства. Meta description — самостоятельное резюме, ориентир120–170 знаков/максимум180 в промпте, технический предел320.

Лексическая проверка отклоняет часть новых свойств/чисел, неподтверждённые утверждения о совместимости и служебные обороты. Она распознаёт типичные смешанные латинские/кириллические буквы в исходнике и формы слов об установке, но **не доказывает истинность всего текста** и не заменяет проверку каждого исполнения владельцем. Допустимость JSON и прохождение фильтра не означают редакторского одобрения.

[Google о полезном контенте](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) не задаёт предпочтительного числа слов. [Руководство по ИИ-контенту](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content) требует проверки фактов и пользы. Не обещаем позиции в поиске или «неопределимость ИИ». Промпт30.09 и первые проверки09.10 сохранены в Git/прежних artifacts; не применять старые регламенты поверх этой версии.

## API и история

- Штатные staff/no-store для GET; Origin/CSRF и JSON до64КиБ для POST. GET `/api/manager/product-ai` возвращает доступные модели, модель по умолчанию, область сотрудника и бюджет. `?request=<UUID>` — только свой запрос; `?history=<productUUID>` — последние12 своих успешных вариантов.
- POST принимает `productId`, текущие `data` формы, `notes` до1500 символов, `provider`, необязательный фиксированный `model`, `idempotencyKey`. При правке — `revision={requestId,description,metaDescription,instruction}`; instruction3–1000 символов. Исходник должен быть успешным запросом того же сотрудника и товара.
- Модели передаются название/категория, значения характеристик, варианты, совместимость, notes; при правке — предыдущие тексты и пожелание к подаче. Не передаются артикулы/коды маркетплейсов, цены, остатки, упаковка, фотографии, SEO-title и данные покупателей. Существующее описание само по себе не становится источником фактов. Справочники разрешаются сервером; собственные свойства и совместимость варианта переопределяют общие.
- Все запросы остаются в `ar_ai_text_requests` (миграция013). `source_facts.editorial` хранит исходный черновик/пожелание к правке, source_hash относится к фактам, input_hash — также к модели, редактуре и версии промпта. Старый журнал не очищается. Новых миграций нет.
- После оплаченного отказа проверки сырой ответ сохраняется в `result.rejectedText` для диагностики; API не выдаёт его как готовое описание и не предлагает применить. Успешная история отделена от таких ответов.
- Браузер сохраняет точное тело ожидающего запроса без ключей API в sessionStorage, в области сотрудника/товара. Завершение сессии через штатный интерфейс удаляет этот снимок. При истечении сессии сервер всё равно требует повторный вход. Предыдущие результаты доступны в серверной истории.
- Генерация и применение в интерфейсе не пишут каталог, черновики редактора, заказы или склад. Публикация использует прежний транзакционный редактор.

## Модели, расходы и сбои

| Модель | Настройки | Верхние тарифы USD/1млн вход/выход |
|---|---|---|
| GPT-6 Luna | reasoning none, максимум1800 выходных токенов |0.125 /0.50 |
| GPT-6.1 Sol | reasoning low, максимум4000, включая рассуждения |2.50 /10.00 |
| DeepSeek Flash (выключен) | без thinking, максимум1800 |0.30 /1.20 |

Тарифы OpenAI сверены14.10 по [модели Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol) и [прайсу](https://developers.openai.com/api/docs/pricing). Верхний вход учитывает cache-write; это учёт приложения, не банковская выписка. Модели/тарифы закреплены в adapters/ai-text.ts; произвольные model/base URL не принимаются. Sol требует `AI_TEXT_ALLOW_SOL=true`; `AI_TEXT_OPENAI_MODEL` задаёт модель по умолчанию, иначе Luna.

Общий бюджет считается по Москве под одной advisory-блокировкой для всех сотрудников/моделей. Лимит приложения ограничен сверху$10. До отправки резервируются UTF-8 длина промпта/входа с запасом2048 и максимальный выход; факты вместе с редактурой ограничены24КиБ. По usage резерв заменяется учтённой верхней стоимостью выбранной модели. Неопределённые исходы сохраняют резерв, в том числе через границу месяца. Несоответствие usage ожидаемым пределам приостанавливает новые вызовы до проверки.

OpenAI — Responses, store=false/service_tier=default через NL; DeepSeek — Chat Completions. Внешнего поиска/tools/автоматического повторения платных запросов нет. Явные отклонения4xx учитываются без оплаты; неправильный/обрезанный оплаченный результат — по usage. Сетевой вызов не удерживает транзакции каталога/склада. Бюджет и шлюз изображений независимы и не изменены.
