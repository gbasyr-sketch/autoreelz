# Единая форма товара в кабинете владельца

30.09.2026 владелец поручил реализовать упрощение после обсуждения предложения. Форма реализована в `/manager/products/edit?id=<UUID>`. Состояние опубликованного выпуска — [status.md](status.md), инструкция — [product-entry-guide.md](product-entry-guide.md).

## Что улучшить

Добавить кнопку **«Добавить товар»** в `/manager/products` и одну форму в существующем светлом стиле кабинета. Сейчас приходится переключаться между товаром, SKU, упаковкой и складом в двух интерфейсах. Все эти данные можно вводить в одном месте, сохранив существующие правила каталога и склада.

## Как выглядит форма

| Область | Содержимое |
|---|---|
| Основное | Название, категория, описание; адрес предлагается из названия с проверкой уникальности, доступен для правки |
| Фотографии | Загрузка или выбор из библиотеки, миниатюры, перенос мышью, отметка главного фото; подписи изображений. Неиспользуемые файлы можно переместить в удалённые и восстановить |
| Исполнения | Изначально одна строка; кнопка «Добавить вариант», таблица: название, артикул, цена в ₽. Например, отдельные цвета подсветки |
| Упаковка | Вес в граммах, размеры в сантиметрах с явными единицами; автоматический точный перевод в миллиметры для существующей БД; выбор общей или отдельной упаковки вариантов |
| Начальный запас | Фактическое количество и причина для каждого нового исполнения. Приход проводится только один раз после успешного создания |
| Характеристики и совместимость | Поля по категории, понятные варианты автомобилей; неподтверждённая применимость не превращается в «Подходит» |
| Дополнительно | SEO-заголовок из названия с возможностью ручной правки, meta description, особые фото/совместимость варианта. Эти поля не должны отвлекать от первого заполнения |
| Предпросмотр | Карточка с главным фото, названием и ценой; список недостающих данных |

Внизу два явных действия: **«Сохранить черновик»** и **«Опубликовать»**. На телефоне блоки идут друг за другом; на компьютере предпросмотр можно показать справа. Ошибки рядом с нужным полем, все подсказки по-русски. Черновик можно сохранить с неполными данными, но с честным указанием, что ещё не заполнено.

## Разумная последовательность

1. Первая версия: отдельные товары, одно или несколько исполнений, фото, цена, упаковка, начальный запас, проверка и публикация. Создание/последующее редактирование должны использовать одни правила.
2. После проверки на реальном наполнении: безопасное создание похожего товара (новые артикулы, без копирования остатка), массовая работа из таблицы с предварительным просмотром, удобный редактор комплектов.

CMS остаётся доступной для сложных справочников. Перенос на другую платформу для такой формы не нужен.

## Что требуется предусмотреть при реализации

- Использовать существующие данные и права; не создавать второй независимый каталог.
- Общие фотографии обязательны для нормального вида каталога; собственные фотографии варианта заменяют галерею по действующим правилам.
- Деньги остаются точными десятичными рублями, склад учитывается по физическим SKU.
- Повтор сохранения после сетевого сбоя не создаёт второй товар, упаковку или повторный приход. Начальный запас — через транзакционную складскую команду с историей, не прямое изменение поля в CMS.
- При редактировании существующего товара не применять начальный запас заново. Для пересчёта использовать отдельную складскую операцию.
- Продумать частичное сохранение, загрузку фото и восстановление после ошибки; не оставлять частично опубликованный товар.
- Проверять уникальность артикулов/slug, соответствие вариантов товару и совместимость; не генерировать неподтверждённые свойства.
- Проверить права, повтор запросов, неполные черновики, конкурирующие правки, несколько SKU, миллиметры/сантиметры, фото, мобильную форму и результат на витрине.

## Реализованный контракт

С07.10 поле SEO-заголовка обычного товара и комплекта показывает название товара, если ручной заголовок не задан. Автоматический режим следует за изменением названия и сохраняется после черновика/публикации/повторного открытия. В данных он по-прежнему обозначается пустым `seoTitle` (при публикации — `seo_title=NULL`): отображаемое имя не превращается незаметно в ручной override. Ввод собственного текста сохраняет его точно и отключает автозамену, даже если он совпал с прежним названием. Кнопка «Использовать название товара» или очистка поля возвращает автоматический режим; после ухода из пустого поля видно текущее название. Одно открытие формы не меняет каталог и не помечает форму изменённой. Ранее введённые заголовки сохраняются. Серверный формат и SEO витрины не менялись: без override остаётся прежний title из названия и бренда, вручную заданный title выводится точно.

- GET `/api/manager/product-editor?options=1` — категории, определения характеристик и автомобили; `?id=<UUID>` — форма; `?drafts=1` — сохранённые черновики. Только действующая сессия владельца через `staff()`, `no-store`.
- POST `/api/manager/product-editor`: `id`, `version`, `baseHash`, `data`, `action=draft|publish|discard`, `idempotencyKey`; строгие Origin/CSRF, предел JSON 64 КиБ. Не более 20 вариантов, 12 фото на галерею, 40 характеристик и 30 правил совместимости на набор.
- Миграция012 добавляет `ar_product_editor_drafts`, `ar_product_editor_uploads`, `ar_product_editor_events` и необходимые гранты `ar_app`. Прежние миграции неизменны. Начальное количество не вводится повторно для уже существующих SKU.
- Черновик хранит неполные данные отдельно, включая незаполненные цену/категорию. При сохранении черновика каталожные записи и склад не меняются. При публикации весь товар, связи, новые упаковки и приход проходят в одной транзакции вместе с результатом идемпотентной команды. Приход использует штатные `lockStock`/`stockMove` и журнал с причиной.
- Версия черновика защищает от двух вкладок; fingerprint всего редактируемого каталожного состояния защищает от правок CMS, включая дочерние записи. При публикации короткая блокировка таблиц сериализует запись с CMS; READ COMMITTED перечитывает актуальное состояние после блокировки. Остатки не входят в fingerprint и не перезаписываются. Устаревший черновик можно явно сбросить после подтверждения в интерфейсе.
- Существующий SKU нельзя незаметно удалить или перенести к другому товару. Можно изменить статус на архив. Дополнительные категории не редактируются этой формой и сохраняются. Изменение упаковки создаёт отдельную запись, не меняя общую коробку других товаров. История адресов работает через прежние триггеры.
- Публикация требует название/slug/опубликованную категорию с родителями, общую фотографию и хотя бы один опубликованный вариант с положительной ценой. Проверяются артикулы, все значения характеристик и связи совместимости. Отсутствие упаковки и неизвестная совместимость остаются честными предупреждениями: не выдумываются тариф или применимость.
- Фото: POST `/api/manager/product-image`, multipart с `id`, `key`, `file`; владелец/Origin/CSRF до чтения. Предел одного файла10 МБ/24 Мп, JPEG/PNG/WebP, проверка содержимого и перекодирование штатным обработчиком в WebP до1600px. Оригинал не сохраняется, EXIF/GPS удаляются. Загрузка в Directus от имени текущего владельца с фиксированным UUID, повтор восстанавливает тот же файл. [Официальный API файлов](https://directus.com/docs/api/files).
- GET `/api/manager/product-image?id=<UUID>` — защищённый предпросмотр только каталожного фото или своей загрузки; до публикации фото не открывается публичным `/media`. При удалении из галереи удаляется связь, а не общий файл CMS. Неиспользованные загрузки остаются в библиотеке CMS; автоматическая очистка не реализована.
- Редактор комплектов, копирование похожего товара и Excel не входят в эту итерацию. Поля не показывают реальные продажи: режим магазина остаётся staging.

03.10 добавлена [библиотека фотографий](product-image-library.md): повторный выбор растровых файлов CMS и обратимое удаление с защитой используемых фото. Расширены серверные правила выбора/предпросмотра, добавлена миграция016; эта поздняя доработка дополняет первоначальный контракт загрузки выше.

Проверки: `tests/product-editor.test.ts`, `tests/product-editor-database.mjs`, `tests/product-editor-browser.mjs`; фактические результаты — `artifacts/product-editor/`. DB-набор допускает только `ar_qa_product_editor_*`; подготавливает синтетические данные. Браузерный набор подменяет API, поэтому отдельная API-проверка использует настоящую авторизацию/загрузку CMS и изолированную торговую БД.

## Главное фото и фотографии исполнений

Первое фото общей галереи используется только исполнениями с `mediaMode=inherit`. Если у цвета стоит `replace` («Свои фотографии варианта»), витрина показывает его собственную галерею и её первое фото, даже если у товара опубликована новая общая обложка. Ссылка с `?sku=` выбирает именно это исполнение; ожидание кеша проблему не меняет.

У каждого фото общей галереи и галереи варианта есть кнопка «Сделать главным…». Она открывает выбранное фото и выбор области: все варианты (цвета) либо одно конкретное исполнение. При открытии из галереи исполнения выбран именно этот вариант. Для комплекта меняется только общая галерея.

- Все варианты: фото перемещается/добавляется первым в общую галерею и каждую собственную (`replace`). Наследующие исполнения сохраняют `inherit` и используют обновлённую общую галерею. Это разовое действие над вариантами текущей формы, не постоянная синхронизация будущих замен.
- Один вариант: общая галерея и остальные SKU не меняются. При `inherit` текущие общие и сохранённые индивидуальные фото копируются без дублей в собственную галерею, режим становится `replace`.
- Существующие фото и их подписи сохраняются, выбранный файл не дублируется. До изменения проверяется лимит12 во всех затронутых галереях. Если места нет, не изменяется ни одна галерея; сообщение называет вариант. Автоматического удаления последнего фото нет.
- Кнопка меняет только несохранённую форму. Для сохранения используется прежний API черновика/публикации с версией, fingerprint и idempotency key. Новых API, миграций, загрузок и платных генераций нет.

ИИ-студия и обычные загрузки добавляют фото в галерею; затем доступна та же кнопка. Перетаскивание и стрелки по-прежнему меняют только порядок своей галереи.
