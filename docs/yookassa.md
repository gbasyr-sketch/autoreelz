# ЮKassa sandbox

Состояние на24.09.2026: тестовая оплата картой подключена к публичному checkout, проверке API, webhook и worker. Реальные деньги, провайдерские возвраты и фискализация не включены. [Контракт](yookassa-checkout-contract.md) · [Состояние](status.md).

## Доступ и конфигурация

Владелец уже предоставил `private/yookassa-sandbox.env` с YOOKASSA_SHOP_ID/YOOKASSA_SECRET_KEY. Файл0600, вне Git, не подхватывается приложением автоматически. Сервер использует свои значения в runtime через server.env; не заменять их целиком локальным .env.

`node scripts/check-yookassa.ts` делает GET/me без создания платежа. Проверяется соответствие shop ID и test=true; live/чужой магазин отклоняется. Прежняя проверка fiscalization_enabled=false — снимок тестового кабинета, не согласованная налоговая настройка.

## Поток оплаты

1. Сервер фиксирует попытку с неизменяемыми суммой RUB, заказом, версией доставки, ключом PSP и return URL.
2. Сеть вызывается вне SQL-транзакции; браузер переходит на разрешённый HTTPS-хост провайдера. Данные банковской карты через формы AUTO REELZ не передаются.
3. Возврат браузера лишь открывает заказ. Статус подтверждается аутентифицированным API, проверяются account/test/id/сумма/валюта/metadata.
4. `https://autoreelz.ru/api/payments/yookassa` открыт для HTTP-уведомлений payment.succeeded/payment.canceled; владелец сохранил их в кабинете. Payload события — повод выполнить GET, не доказательство оплаты сам по себе.
5. Worker восстанавливает проверку незавершённых попыток. После500/таймаута POST исход неизвестен: повторяют тот же ключ и запрос, не создают новую оплату.

Поздний платёж или расхождение → manual_review. Склад не списывается повторно. Старый HMAC имитатора не является подписью ЮKassa. Sandbox-клиент создаёт оплату картой; прежняя локальная кнопка СБП не доказывает реальную интеграцию СБП.

## Доработка и откат

Миграция010 применена, не редактировать. До выпуска проверить попытку/lease/идемпотентность, одновременные callback+worker, позднюю оплату, отмену и закрытый доступ другой сессии. Откат к старому app6ab6bea с имитатором небезопасен для незавершённых PSP-платежей.

Следующие задачи B02/B03 — касса/ОФД, налоговые параметры, чеки, провайдерские возвраты, live и СБП. Требуется отдельное поручение реальных операций; смена STORE_MODE не снимает текущих программных ограничений. Перед новой интеграцией сверить [официальное тестирование](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) и [формат API](https://yookassa.ru/developers/using-api/interaction-format) на дату работ.
