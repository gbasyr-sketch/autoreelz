## Что подтверждено официальной документацией

[Чеки от ЮKassa](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/basics) работают без самостоятельного подключения кассы/фискального накопителя; сервис взимает отдельную комиссию за успешный платёж. Конкретный тариф нужно посмотреть в кабинете/договоре, число не предполагается. Чеки доставляются по email, отдельный магазинный SMTP для их доставки не нужен.

[При оплате](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/payments) сведения передаются в receipt вместе с каждым платежом. Для полной предоплаты товаров до выдачи — соответствующий признак предоплаты; при выдаче нужен отдельный чек зачёта предоплаты с full_payment и settlements/prepayment. Не считать отправку посылки автоматически выдачей без принятого процесса. Точный момент/источник события закрывающего чека, возврат после выдачи и частичные исходы необходимо определить до реализации.

[Без НДС](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/parameters-values) — vat_code=1, это не ставка0%. Налоговая система и доступность услуги должны совпадать с рабочим кабинетом; не добавлять неподтверждённые поля API по аналогии с другой кассой.

[Полный возврат](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/refunds) для этого сервиса не требует передачи receipt: ЮKassa использует исходный чек. Его регистрацию отслеживают отдельно по receipt_registration. Частичный возврат требует состава чека.

[Обычная sandbox-проверка чеков](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing#receipts) описана для сторонней онлайн-кассы. Не выдавать её за проверку именно «Чеков от ЮKassa». Для этой услуги официальная инструкция предлагает минимальную оплату с проверкой чека и возвратом; реальные деньги и доставка чеков потребуют отдельного поручения после готовой интеграции.
