# Видео в карточке товара

11.10.2026 владелец поручил реализовать один ролик по ссылке VK или RUTUBE. Общий ролик относится к товару, включая комплект; отдельные видео по цветам не предусмотрены. Состояние выпуска — [status.md](status.md).

## Для владельца

В `/manager/products/edit` под фотографиями расположен блок **«Видео товара»**. Вставьте ссылку на отдельный ролик и нажмите **«Проверить видео»**. Плеер открывается в окне; распознанная ссылка не гарантирует доступность ролика у провайдера. После проверки сохраните черновик либо опубликуйте изменения отдельно. **«Убрать видео»** очищает поле формы; на сайте ролик исчезнет только после публикации.

На витрине рядом с фотографиями появляется миниатюра **«Видео»** с кнопкой воспроизведения. Для её фона используется фото текущего исполнения, а не автоматически скачанное изображение видеохостинга. Фото сохраняют порядок и свайпы; видео не меняет главное фото и счётчик фотографий. При закрытии окна плеер удаляется и воспроизведение прекращается. Ссылка «Открыть на…» остаётся доступна, если сервис не разрешает встроенный просмотр. Без JavaScript показывается обычная ссылка.

## Ссылки и границы

- RUTUBE: HTTPS-ссылки `/video/<32hex>`, `/shorts/<32hex>` и `/play/embed/<32hex>`. Служебные параметры вроде `?r=wd` удаляются при публикации. Для этой версии нужны публичные ролики; ссылки с приватным ключом `p` не принимаются.
- VK: прямые ссылки `/video<owner>_<id>` на `vk.com`, `m.vk.com`, `vk.ru`, `vkvideo.ru`; также `/video_ext.php?oid=…&id=…&hash=…`. При наличии hash он сохраняется для плеера. Каналы, плейлисты, сокращённые ссылки, клипы и HTML-код не поддерживаются. Результат направляется на фиксированный хост `vkvideo.ru`.
- Воспроизведение зависит от доступности видео и настроек встраивания на видеохостинге. Для VK при ограничении прямой ссылки можно указать ссылку плеера из экспорта. Реальный ролик VK владелец пока не предоставил; это не проверка его видео.
- Плеер создаётся только после нажатия, autoplay выключен. Магазин не скачивает и не хранит видеофайл, не делает серверных запросов по пользовательскому URL. Ключи/API/платная генерация не используются.
- Параметры iframe формируются по allowlist: HTTPS, точные хосты/пути/идентификаторы; credentials, порты, фрагменты, HTML, исполняемые схемы и повторяющиеся идентификаторы запрещены. Сторонние query-параметры не переносятся. Клиент и сервер используют один разбор ссылки.

## Хранение и совместимость

Миграция022 добавляет nullable `ar_products.video_url`. Черновик хранит `videoUrl` в прежнем JSON, его публикация проходит штатной транзакцией manager вместе с остальными данными, версией и idempotency key. Сохранить незавершённый/неверный URL в черновик можно; публикация отклонит его с ошибкой у поля. Пустая строка при публикации удаляет видео. Отсутствие поля у старого клиента сохраняет опубликованное значение.

NULL-колонка исключается из fingerprint товара: добавление миграции не делает прежние сохранённые черновики устаревшими. Непустая ссылка учитывается в fingerprint, поэтому внешние изменения видео вызывают обычный конфликт редактирования. Старые черновики без поля получают текущее опубликованное значение при чтении. Миграция не переписывает каталог/черновики и не меняет склад или фотографии.

Новые публичные API не добавлены. Права manager, Origin/CSRF, лимит тела запроса и защита файлов остаются штатными. Статьи используют прежний `normalizeVideoUrl`: изменение нормализатора товаров не расширяет автоматически входы редактора статей.

Внешние плееры подменены в этом сценарии. Нужен отдельно запущенный `tests/helpers/ai-image-preview.mjs` с уникальными именем БД/каталогом, simulation и worker off.
