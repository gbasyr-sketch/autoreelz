# Обзор магазина — контракт

29.09.2026 владелец согласовал светлый дашборд в `/manager` по предложенному эскизу. 30.09 кабинет разделён: список `/manager/orders`, карточка `/manager/orders/[id]`, склад `/manager/stock`; остальные разделы — [manager-workspace.md](manager-workspace.md). Существующие команды сохраняются. CMS остаётся редактором товаров и статей. Старые ссылки с `#manager-*` переводятся на страницу операций.

Доступ: только сотрудник с правом торговых операций через существующую CMS-сессию; API no-store. До входа отдаётся оболочка без данных. Эскизные суммы и отзывы не используются.

- Периоды: сегодня,7,30 календарных дней по Москве, включая текущий неполный день. Оплаты группируются по времени первого принятого события `ar_payment_events.outcome=paid`, не по времени создания заказа. Только succeeded, согласованные paid-статусы заказа и проверенные тестовые провайдеры; повторные события/попытки не удваивают заказ. Товары и доставка отдельно, средний чек по товарам, обычные/предзаказы отдельно. Текущий магазин работает только в тестовой среде: обзор честно помечен, реальные продажи ещё не подключены. Для будущего live нужны постоянная маркировка среды заказа и поддержка реального провайдера; текущие исторические заказы не превращать в реальные переключением env.
- Очереди задач и заказов в работе — текущее состояние за всё время, независимо от периода графика. Истёкшие ожидания оплаты не считать активными. Фильтры: все/обычные/предзаказы, ждут сборки, уточнение доставки, подтверждение предзаказа, проверка оплаты. В обзоре показаны последние5 заказов; полные очереди открываются в списке с серверной пагинацией по20. Переход к конкретному заказу работает независимо от его возраста.
- Склад вынесен в отдельный раздел; обзор показывает только счётчик низких остатков. Данные сводки: недемонстрационные активные физические SKU, on_hand/reserved/free; настраиваемый общий порог низкого свободного остатка0–100. Порог и фильтры сохраняются только в браузере, денег/данных покупателей в localStorage нет. У комплектов отдельного остатка нет: доступность по составляющим.
- Готовность каталога: обзор показывает счётчик, подробности находятся в `/manager/products`. Проверки: нет эффективного фото, упаковки SKU, подтверждённого правила совместимости; учитываются режимы inherit/replace. Для комплектов — состав и данные компонентов. Демо/архив исключены. Пустое описание и отсутствие опубликованного исполнения отмечаются отдельно. Счётчик — товары, не сумма всех проблем.
- Автообновление каждые60сек только видимой страницы, без параллельных запросов и без сброса фильтров. Сбой сохраняет прежние показатели с предупреждением и временем последнего успешного ответа;401/403 скрывает данные и возвращает вход. Пустой период показывает ноль и пояснение. Недоступный ответ не заменяется нулями.

Без новых миграций, изменений остатков, заказов или настроек платежей. Посещаемость/конверсия и прибыль отложены до подключения аналитики и данных о себестоимости. Сетевую проблему B13 по просьбе владельца не исследовать.

## Выход и ссылки

По уточнениям владельца: кнопка «Выйти» есть на обзоре, заказах/складе, описаниях и модерации. POST проходит Origin/CSRF-проверку, отзывает текущую CMS-сессию через Directus `/auth/logout` в режиме session, затем удаляет её HttpOnly-cookie. Если CMS недоступна, выход не объявляется успешным: данные скрываются, доступна повторная попытка. Покупательская сессия/корзина не удаляются. Другие вкладки нашего кабинета получают сигнал выхода, возврат из bfcache требует нового чтения. Тестировать отзыв старого cookie на API, а не только исчезновение кнопок.

Ссылки «Открыть CMS», «Товары в CMS» и «Статьи» на сервере ведут в `/cms/admin`; локальный localhost используется только при STORE_MODE=local-test. Старую фиксированную ссылку127.0.0.1 со страницы заказов убрали.

В обзоре больше нет длинных таблиц склада/готовности и форм операций; задача открывает соответствующий раздел с фильтром.
