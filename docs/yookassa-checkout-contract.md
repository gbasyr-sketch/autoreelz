# Тестовая ЮKassa в заказе

Продолжение этапа7. Владелец заполнил ключи; GET /me подтвердил test=true, доступность карты и отключённую фискализацию. Реальные деньги, чеки/возвраты денег и сообщения не включать. HTTP-фикстуры не заменяют полный платёж в sandbox.

- PAYMENT_PROVIDER по умолчанию simulation. yookassa-sandbox включается явно только в local-test/staging. Каждый POST провайдера предваряет GET /me с test=true/нужным shopId; фискализация без согласованного чека блокируется. Только карта; СБП пока остаётся в имитаторе.
- Один pending-платёж на заказ. Provider, shopId, ключ запроса, сумма/RUB, версия доставки и return URL сохраняются до сети и не меняются. Повтор с другим клиентским ключом использует существующий pending; симулятор не может подтвердить запись ЮKassa.
- Сеть вне SQL-транзакции. Короткая lease ограничивает параллельные вызовы; после потери процесса повторяется прежний provider key/тело, не создаётся новый. Неопределённый исход не считается отказом. За пределами безопасного окна идемпотентности автоматического POST нет.
- Новый POST только пока заказ допускает оплату. После отмены/истечения GET известного платежа продолжается для выявления позднего успеха; без известного ID новый POST запрещён. Callback может подсказать ID, но результат и связь с заказом подтверждаются отдельным GET.
- Webhook имеет отдельный точный путь, без Basic/CSRF, но с ограничением тела/частоты и проверкой данных через API. Не использовать вымышленную HMAC-подпись ЮKassa. Ответ не содержит данных заказа. Неизвестные UUID игнорируются без сетевого вызова.
- Успех/отмена провайдера атомарно обновляют платёж и общий торговый журнал. Сохраняются однократное списание, возврат по30минутам, защита чужих заказов и manual_review поздней оплаты. URL возврата не меняет статус.
- В интерфейсе: переход на тестовую страницу карты, продолжение того же платежа, проверка статуса. Пока результат неизвестен — понятное ожидание, без предложения повторно списать деньги.
- Проверки на отдельной QA-базе: повторы/параллельность, потерянный ответ, смена суммы/магазина, поддельный webhook/симулятор, чужой заказ, отмена/истечение/поздний успех, отсутствие раннего резерва предзаказа и сохранность simulation.
